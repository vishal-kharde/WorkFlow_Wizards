# Data Mapping Document

## Source
`data/sample_tasks.csv` is a synthetic daily operations task file. No real customer or bank data should be used.

| CSV column | Target database field | Type | Validation / transformation |
|---|---|---|---|
| `task_id` | `ops_tasks.task_id` | TEXT, primary key | Required; unique within file and database |
| `trade_date` | `ops_tasks.trade_date` | TEXT (ISO date) | Required; must be `YYYY-MM-DD` |
| `team` | `ops_tasks.team` | TEXT | Required; trim leading/trailing spaces |
| `task_type` | `ops_tasks.task_type` | TEXT | Required; trim whitespace |
| `status` | `ops_tasks.status` | TEXT | Required; New, In Progress, Completed, On Hold |
| `priority` | `ops_tasks.priority` | TEXT | Required; Low, Medium, High, Critical |
| `owner` | `ops_tasks.owner` | TEXT | Required; trim whitespace |
| `amount_usd` | `ops_tasks.amount_usd` | REAL | Numeric and non-negative |
| `notes` | `ops_tasks.notes` | TEXT | Optional; trim whitespace |

## Processing rules
1. Required columns must exist; otherwise the file is rejected before processing.
2. Text fields are trimmed.
3. Status and priority values are normalized to the expected title case.
4. Invalid rows are written to `output/exceptions.csv` with a reason.
5. Valid rows are inserted into SQLite.
6. A task ID already present in the database is skipped and recorded in `processing_audit`.
7. `created_at_utc` and audit timestamps are generated by the script.
8. A summary report and log are produced for each run.

## Important limitation
This is an internship prototype, not a production banking application. Before production use, add access control, secure secret management, retention policies, monitoring, approved data handling, transaction controls and operational sign-off.
